# Optional Work v0.1 reproduction

This separate research path runs interactive Pi agents for C3 first/repeat and C6 first/repeat rounds, each with a fixed 180-second budget. It is never part of install or smoke. Use a drained Tempo endpoint with its normal guards and controller relay already running. The runner observes ownership and resources and stops only its own Pi process groups on a fault; it never launches or stops model services.

The public task prompts in [prompts.json](prompts.json) are synthetic: build an orbital UI, implement/test a standard-library N-body simulation, and repair a seeded two-request Cadence scheduler bug. There are no private sessions or user prompts. [fixture.json](fixture.json) pins public `jakejharris/jspark3` revision `1507c05b7a7fe384369df200e44cecb05bd9d2ff`, its public download, every historical fixture file hash, and the exact injected one-line defect. The two other workspaces begin empty. Public archive framing differs from the original git archive; preparation verifies the complete extracted, seeded file set is identical. Fixtures are downloaded separately to retain their own notices and licenses.

Run this on a separate Linux research client with access to the controller's frozen Tempo config/ownership receipt and SSH aliases. Keeping interactive agents off serving Sparks avoids mixing client memory/CPU into serving conditions. The client requires Python 3.10+, Node 22.12.0, Pi `@earendil-works/pi-coding-agent@0.84.2`, and `/usr/bin/bwrap` (Bubblewrap with unprivileged user namespaces enabled). Install these through normal client setup; for Pi, `npm install --prefix /YOUR/PI/PREFIX @earendil-works/pi-coding-agent@0.84.2` creates `/YOUR/PI/PREFIX/node_modules/.bin/pi`. Set Node's directory on PATH. No private Pi configuration or credentials are needed. The public local endpoint adapter is generated from scratch with compaction/retry disabled.

For a separate client, copy only the controller's frozen `config.json` and `state_dir/deployment/{owned.json,config.json}` into a private client directory. Choose a writable absolute client `state_dir`, preserving the `deployment` subdirectory. Update only `state_dir` in both the client command config and its copied deployment `config.json` to that same path; they must remain equal. Keep deployment, exact IDs/start times, model/image and all remote paths unchanged. Configure the existing `ssh` alias names to reach the same ranks from this client and verify `ssh -o BatchMode=yes ALIAS true` for each. Do not copy private keys through the recipe. These are observer receipts; do not run lifecycle `start`, `stop` or `relay` from the research client. Keep the original controller and its relay running.

From the recipe checkout, choose new writable local paths and your endpoint:

```bash
python3 benchmarks/work/prepare.py --destination /srv/research/work-inputs --archive /srv/research/cadence-fixture.tar.gz --endpoint http://192.0.2.11:8888
python3 benchmarks/work/run.py --config config.json --prepared /srv/research/work-inputs --output /srv/research/work-check --pi /YOUR/PI/PREFIX/node_modules/.bin/pi --check-only
python3 benchmarks/work/run.py --config config.json --prepared /srv/research/work-inputs --output /srv/research/work-smoke --pi /YOUR/PI/PREFIX/node_modules/.bin/pi --smoke
python3 benchmarks/work/run.py --config config.json --prepared /srv/research/work-inputs --output /srv/research/work-full --pi /YOUR/PI/PREFIX/node_modules/.bin/pi
```

`--check-only` verifies Pi version, actual Bubblewrap namespaces, public fixture/adapter hashes, current guarded rank identities and idle engine gauges without inference. `--smoke` runs one 45-second tool task. A full run starts three agents (one of each task), then repeats; it next starts six agents (two of each task), then repeats. Every slot gets a new workspace; first/repeat means the same prompt/fixture with retained engine caches, not continuing a Pi session. Use a fresh service incarnation and the same explicit warmup sequence when comparing cohorts. The small smoke above itself warms caches: record whether it ran. Historical results did not certify universally cold kernels or cache state.

Each agent uses `--thinking high` (mapped to request effort `xhigh`), temperature 0, a 65536-token request cap, JSON output, tools read/write/edit/bash, and no session/extensions/skills/context files/prompt templates/themes. The sole explicit observer extension fixes the outgoing payload and records it. Bash has no network and can write only its own workspace and ephemeral `/tmp`; file tools reject paths outside the workspace, including symlink escapes. Missing sandbox support fails before inference. The portable wrapper adds path checks, bounded termination escalation and current Tempo guard observation, so it is an adapted orchestration implementation, not a bit-identical historical executable.

`RESULT.json` for each round records raw engine counters, each slot's completed-message token usage, tool/model errors, first-output timing, payload hashes and cutoff status. The engine measure is **generation-token counter delta over launch/drain divided by 180 seconds**, including tokens from unfinished turns. It is not completed-task throughput or a quality score. Short 45-second smoke results use their own denominator and must not be compared with published Work rows. Early completion, errors and cap/cutoff are visible; failed transport/configuration does not produce `COMPLETE.json`. Counter resets, missing queue gauges, guard/identity faults and service swap fail the run. Other clients invalidate engine attribution: keep them drained throughout.

Outputs include locally generated code, model text and payloads; review them before sharing. Nothing is uploaded. Failed or interrupted output directories are retained, and reruns need a new `--output` path. Do not overwrite published historical measurements: every reproduction is a new cohort. Quality evaluation, if desired, is separate from Work's token metric.
